# تجربة (Tajruba)

منصة عربية ثنائية اللغة لقياس تجربة المريض **PREMs**، النتائج الصحية المبلغة من
المريض **PROMs**، وذكاء التعليقات مع استعادة الخدمة (Service Recovery)، مبنية
كمشروع Node.js/TypeScript كامل (خادم + واجهة) بدون أي اعتماد خارجي مدفوع.

## البنية التقنية

- **الخادم**: Express + TypeScript، يعمل عبر `tsx` مباشرة (بدون خطوة بناء منفصلة للخادم).
- **قاعدة البيانات**: SQLite عبر `node:sqlite` المدمجة في Node 22 (ملف واحد، بدون تثبيت خارجي)، بمخطط مصمم للترحيل لاحقًا إلى PostgreSQL + Row-Level Security.
- **الواجهة**: React 18 + React Router + Tailwind CSS v4 + Recharts، مبنية عبر Vite.
- **المصادقة**: جلسات مبنية على كوكي HttpOnly مع تجزئة كلمات المرور بـ `scrypt` (بدون مكتبات جلسات خارجية).
- **الذكاء الاصطناعي للتعليقات**: محلّل قواعد محلي (Rule-Based) لا يرسل أي نص خام إلى أي API خارجي — راجع قسم PDPL أدناه.

```
tajruba/
├── server/
│   ├── db.ts            # مخطط SQLite الكامل
│   ├── types.ts          # الأنواع المشتركة (الأدوار، الخدمات، التصنيفات...)
│   ├── auth.ts           # كلمات المرور، الجلسات، RBAC
│   ├── scoring.ts        # محرك حساب PREMs وPROMs (مع اختباراته)
│   ├── comments.ts       # إخفاء الهوية (PII) + التصنيف والخطورة (مع اختباراته)
│   ├── seed.ts           # بيانات تجريبية كاملة وقابلة لإعادة التوليد
│   ├── seed-data/        # بنك الأسئلة وبنك التعليقات التجريبية (JSON)
│   └── api.ts            # كل نقاط REST API
├── server.ts             # نقطة الدخول (Express + Vite middleware)
├── src/                  # الواجهة (React)
│   └── pages/            # الاستبيان العام + لوحة التحكم بكل أقسامها
├── tests/                # اختبارات الحساب، التعليقات، RBAC/عزل المستأجرين
```

## ما تم تنفيذه

- تسجيل دخول حقيقي مع صلاحيات RBAC أربعة: `SystemAdmin`، `QualityManager`،
  `DepartmentManager` (مقيّد بقسمه)، `ExecutiveViewer`.
- عزل بيانات كامل حسب `tenant_id` على مستوى كل استعلام (مُختبر بشكل صريح).
- بنك أسئلة PREMs أصلي (**67 سؤالًا** موزّعة على 40 محورًا) يغطي 7 خدمات: الطوارئ،
  التنويم، العيادات الخارجية، الرعاية المنزلية، المختبر، الأشعة، الصيدلية — مع
  قوالب استبيان جاهزة لكل خدمة.
- استبيان مريض عام عبر رابط برمز (Token) بدون تسجيل دخول، مع دعوات تنتهي صلاحيتها
  ولا يمكن إكمالها مرتين.
- محرك حساب PREMs: المتوسط، نسبة Top Box، NPS، ومقارنة كل محور بمعيار مرجعي مع
  تحذير العينة الصغيرة (n < 30).
- ذكاء التعليقات: إخفاء تلقائي للهوية (جوال، هوية وطنية، رقم ملف، بريد إلكتروني)
  **قبل** أي تحليل، ثم تصنيف وتحليل مشاعر وخطورة (1-5)، مع تنبيه فوري للخطورة ≥ 4.
- استعادة الخدمة (Service Recovery): دورة حياة موثّقة جديد ← مُسند ← تحت المعالجة
  ← مغلق، وإغلاق الحالة يتطلب صلاحية مدير الجودة (متطلب توثيق CBAHI).
- PROMs: كتالوج أدوات (PHQ-9، GAD-7، VAS مجانية وفعّالة؛ Oxford Knee وEQ-5D-5L
  كـ Metadata محجوبة البنود حتى توثيق الترخيص)، مسار رعاية "استبدال مفصل الركبة"
  بخمس نقاط قياس، وحساب دلتا التحسن مقابل الحد السريري MCID.
- سجل تدقيق (Audit Trail) لكل عملية حساسة.
- استوديو استبيانات لإرسال دعوات بالجملة، ومركز بيانات لعرض سجل التدقيق.

## التشغيل

يتطلب **Node.js 22.5 أو أحدث** بسبب استخدام `node:sqlite`.

```bash
cp .env.example .env
npm install
npm run dev
```

ثم افتح:

```text
http://localhost:3000
```

أو على macOS، انقر مرتين على `RUN_ME.command` (يثبت الاعتماديات تلقائيًا في أول تشغيل).

## خصوصية التعليقات (PDPL)

كل تعليق نصي من المريض يمر أولًا عبر طبقة إخفاء هوية محلية (`server/comments.ts`)
تزيل أرقام الجوال، الهوية الوطنية، رقم الملف، والبريد الإلكتروني، **قبل** أي
تحليل. التحليل نفسه محلي بالكامل (قواعد Rule-Based) في هذا الإصدار — لا يُرسل أي
نص إلى أي API خارجي. عند الرغبة مستقبلًا بربط نموذج ذكاء اصطناعي خارجي، يجب أن
يُطبَّق عبر واجهة `CommentAnalyzer` نفسها، وأن يتلقى فقط `redactedText` وليس
النص الخام أبدًا.

## ملاحظة PROMs

راجع [`docs/SAUDI_PROM_ALIGNMENT.md`](docs/SAUDI_PROM_ALIGNMENT.md) لتفاصيل حالة
ترخيص كل أداة، ولماذا لا تُستخدم بنود Oxford Knee Score وEQ-5D-5L الفعلية حتى
توثيق الترخيص التجاري.

## قبل الإنتاج

هذه نسخة **Pilot** تعمل محليًا، وليست اعتمادًا نهائيًا للنشر السريري. قبل أي نشر إنتاجي حقيقي يجب:

- ترحيل قاعدة البيانات من SQLite إلى PostgreSQL وتطبيق Row-Level Security فعليًا.
- استخدام SSO/MFA ومدير أسرار مركزي بدلًا من كلمة سر جلسة واحدة في `.env`.
- تشغيل تقييم أثر حماية البيانات (DPIA) ومراجعة PDPL وسياسة الاحتفاظ بالبيانات.
- تشفير النسخ الاحتياطية والمرفقات، وربط السجلات بنظام SIEM.
- إجراء اختبار اختراق مستقل قبل أي استخدام مع بيانات مرضى حقيقية.
- الحصول على تراخيص أدوات PROMs المقيّدة (Oxford Knee، EQ-5D-5L) قبل تفعيلها.
- استبدال بيانات Seed التجريبية بالتكامل الفعلي مع أنظمة HIS/EMR ومزوّد SMS/WhatsApp حقيقي (حاليًا الدعوات تُخزَّن فقط ولا تُرسَل فعليًا).
